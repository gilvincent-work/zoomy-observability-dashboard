2. `src/reprice-labels.ts` — pure module (no React/data-layer imports): `guardrailLabel`, `skipLabel`, `nextAction`, `reasonFor`, `summarise`, `discountPct`.

7. `components/analyst/dashboard-shell.tsx` — added `{href: '/repricer', label: 'Repricer', icon: Tag}` to `TABS`, inserted between Traffic and Settings (existing entries untouched, order otherwise preserved). Imported `Tag` from `lucide-react`.
8. Testing: `npm i -D vitest`, added `"test": "vitest run"` to `package.json` scripts. `test/reprice-labels.test.ts` — 10 unit tests covering every guardrail/skip label, `reasonFor` precedence, `summarise` counting/grouping, `discountPct` (20% for 169→135, null when reference price missing), `nextAction` (no-floor hint, null for applied row).

## Deviations from the spec

- None substantive. One judgment call: `summarise`'s `skipped` grouping is keyed by the *label text* (via `reasonFor`), not the raw enum, since two different raw reasons never collapse to the same label in this schema — this keeps the map trivially correct and avoids a second lookup.
- `discountPct` guards `referencePrice === 0` (treated as "missing" for the purposes of a percentage) in addition to `null`, to avoid a divide-by-zero edge case not explicitly specified.

## Things I'm not fully certain about

- I could not verify the page against a live Supabase archive project (no env vars configured in this environment) — verification is via the mock-data path only, exercised through `next build`'s static/type checks and the page rendering server component. The real Supabase read path (`getLatestRepriceRun`'s two-query flow) is implemented per the health-data.ts pattern but is unit-untested since there's no DB fixture; this matches the instruction not to add DOM/component test infra, but means the live-query path is unverified beyond type-checking.
- `RunBadge`/copy wording is my own plain-English rendering of the spec's badge text ("DRY RUN — nothing was changed" / "APPLIED — prices were updated") — implemented with sentence case in the badge as "Dry run — nothing was changed" / "Applied — prices were updated" (uppercase via `uppercase` Tailwind class) to match the visual style of existing badges in the app; functionally identical wording.

## QA round 2 — fixes (2026-08-23)

QA ran the page against the live archive Supabase table (real run history, newest first: `77c6a07a` dry/0 priced, `02d447ad` dry/0 priced, `71cc49ce` **applied, 1 priced/1 applied**, `dc90a9c9` dry/1 priced) and found two issues.

**Finding 1 — missing React key.** `ChangedTable`'s `tbody` mapped rows without a `key` prop, only caught once real data (with a genuinely applied row) rendered. Fixed in `components/analyst/repricer-view.tsx`: `rows.map((r, i) => ...)` now derives `key = r.shopifyVariantId ?? r.marketplaceSku ?? String(i)`. Audited every other `.map()` in the file: the skip-group list (`summary.skipped.map`) already had `key={g.reason}` (reasons are unique per group by construction of `summarise`); `changedRows.map(discountPct)` and `discounts.reduce(...)` are non-JSX and don't need one. No other omissions found.

**Finding 2 — misleading empty state.** When the latest run is a no-op (prices already at target), the "What changed" table was empty with no indication that a real price change happened minutes earlier. Fixed by:
- `src/reprice-types.ts` — added `LastChangeSummary {ranAt, count}`.
- `src/reprice-data.ts` — added `getLastChangeSummary()`: finds the most recent row with `applied = true` (ordered by `ran_at desc`, limit 1), then counts how many rows in that same `run_id` have `applied = true`. Returns `null` when no price has ever been applied. Same `server-only`/`cache`/`noStore`/env-gated-mock-fallback posture as `getLatestRepriceRun`; never throws on unset env — returns `MOCK_LAST_CHANGE` in that case, matching the existing mock pattern.
- `src/reprice-mock.ts` — added `MOCK_LAST_CHANGE = {ranAt: '2026-08-17T05:50:00.000Z', count: 1}` representing a prior run that applied one change, ahead of the no-op `MOCK_REPRICE_RUN`.
- `app/repricer/page.tsx` — fetches both `getLatestRepriceRun()` and `getLastChangeSummary()` in parallel via `Promise.all`, passes `lastChange` into `RepricerView` as an optional prop.
- `components/analyst/repricer-view.tsx` — `RepricerView` now accepts `lastChange?: LastChangeSummary | null`. The "What changed" empty state keeps its existing "most common reason" line and, only when `lastChange` is non-null, adds a second line: "Last actual price change: {count} price(s) updated on {date}." When `lastChange` is `null`, the empty state is unchanged from before.

No changes to the pure `reprice-labels.ts` module were needed for either fix, so `test/reprice-labels.test.ts` was left as-is (still 10/10 passing) per the coordinator's instruction to only extend it if the pure module changed. `getLastChangeSummary` has no unit test (no runner for server-only Supabase calls, per instruction) but is fully typed and returns `null`/mock rather than throwing when env is unset, mirroring `getLatestRepriceRun`.

## Update — 2026-08-23: fixed the "did we actually change anything" confusion

**Root cause fix**: the page described the latest job execution, not the state of
the store. A user saw "DRY RUN — NOTHING WAS CHANGED" on a later no-op run and
didn't realize an earlier run had already applied a live price change. Restructured
so the page leads with store state and demotes run detail below it.

   ONLY — this run wrote nothing"; applied → "APPLIED — this run wrote N price(s)"),
